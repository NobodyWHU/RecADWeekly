# 电商广告研究周报 Agent 配置说明

- **任务名称**：电商广告研究周报（`ecommerce-ads-research-report`）
- **调度周期**：`CRON_TZ=Asia/Shanghai 0 8 * * 1,5`（每周一、周五北京时间 08:00）
- **完整 Sidecar 配置文件**：[sidecar.json](./sidecar.json)（本地部署时请将 `<HOME>` 替换为实际用户主目录并放至 `~/.gemini/config/sidecars/ecommerce-ads-research-report/sidecar.json`）

---

## Agent 执行 Prompt

执行「电商广告研究周报」定时研究任务。项目根目录固定为 `<HOME>/.gemini/antigravity/scratch/ecommerce-ads-research`。请严格按以下步骤与规范执行：

1. **读取历史与去重检查**：
   - 先使用 `read_file` 读取 `covered-papers.json`。
   - 根据其中的 `recent_reports` 列表，使用 `read_file` 读取最近两期报告文件（路径相对于项目根目录）。
   - 如首次运行或缺少历史记录，须在报告开头如实说明，不得假装已完成跨周去重。

2. **严格近 7 天优先的联网检索（使用内置 `search_web` 工具）**：
   - 先确定当前 Asia/Shanghai 日期 `D` 及精确的过去 7 天窗口 `[D-7天, D]`。
   - 检索 arXiv 时**必须优先使用具体日历日期字符串（如 `"DD Mon YYYY"` 逐日或分段组合）与当月 arXiv 编号前缀（`YYMM.`）**定向检索过去 7 天新发布的 `cs.IR` / `cs.LG` / `cs.AI` 论文、技术报告、官方工程博客和高质量工程分析，严禁只搜宽泛年份导致返回数月前的旧论文。
   - 精选条目**优先全部来自过去 7 天**；仅当过去 7 天高质量新增不足 3 项时，才可少量补充过去 8–30 天内尚未覆盖的重要研究，并明确标注为“近期补充”；除非旧论文在过去 7 天内出现实质版本更新（如 v2/v3）、官方代码发布或新增关键实验，否则**绝不拉入数月前的旧文凑数**。
   - 明确每项研究的精确发布日期与版本变化（如 v1/v2）；对 `covered-papers.json` 中已覆盖的旧论文，仅在出现实质版本更新、官方代码发布或新增关键实验时重新推荐，并明确写出变化，绝不重复推荐无更新内容。

3. **优先关注领域**：
   1. 召回排序一体化；
   2. 商业价值建模：bid、eCPM、广告收入、多目标优化；
   3. 解码优化：Lazy Decoder、beam search、Trie、缓存与效率；
   4. 训推一致性；
   5. 语义/商业 SID、listwise 与偏好优化、长序列和长尾覆盖。
   - 若过去 7 天在某个核心维度（如实时 bid/eCPM 嵌入）确实缺乏新增研究，应在「核心变化和工作判断」中如实指出该窗口期空白，不要强行用旧论文填充。

4. **讨论背景**：
   - 千万级 SKU，GR 召回 Top600 后接精排与竞价；重点关注 bid 全链路嵌入、解码效率、长尾覆盖和训推一致性。不要假设任何方案已在业务中实施或取得收益。

5. **输出结构（中文，深度适合工作参考，约 2000–3000 字；高质量新增不足时缩短，不凑数）**：
   - 一、本期核心变化和工作判断；
   - 二、精选 3–7 项研究（逐项说明：问题、机制、相对已有方法的变化、关键实验与基线、可信度与证据范围、局限、业务启发和适用条件）；
   - 三、最值得精读的 1–2 项（指出具体章节或图表，附推荐理由和原文链接）；
   - 四、可用于工作讨论的验证假设与后续关注信号。

6. **严格证据要求**：
   - 仅使用原论文、作者报告、官方工程材料和作者代码支持技术结论。
   - 明确区分预印本/同行评审、公开基准/工业离线/在线 A/B，以及代码开源与独立复现状态。
   - 明确标注【作者报告】、【分析推断】与【待验证建议】。
   - 业务收益优先报告广告收入；若来源仅披露 GMV 或广告主转化价值等代理指标，保留原口径并明确注明「不能等同于平台广告收入」。
   - 严禁直接移植论文收益数字，严禁虚构来源、日期、版本、实验、章节图表号与引用；全文无法读取时明确说明证据范围。

7. **持久化与保存**：
   - 使用 `write_file` 将完整周报保存至 `reports/YYYY-MM-DD.md`（日期取当前 Asia/Shanghai 日期）。
   - 更新 `covered-papers.json`：更新 `last_updated`，将本期报告相对路径追加到 `recent_reports`，并将本期新覆盖或有版本更新的研究写入/更新到 `papers` 数组（包含 `title`、`id_or_url`、`url`、`published_date`、`read_version`、`covered_date`、`key_findings`）。
   - 不要关闭或修改任何其他平台的任务。
